# ZEFM v37 — Notes and legacy database migration

## Recovered behavior from Java source

The original `ZEdit/Annotate.java` calls `QuickEditor` for the word at the
caret or the current selection, using `(filename, word)` as the database key.
`ZEdit/QuickEditor.java` reads, saves, and deletes entries in the MySQL
`notes` table. Each entry has **filename**, **word**, **link**, **data**.
Notes can occur in ordinary documents or in files generated by the browser
and mail features. This means they are **not** exclusively email annotations.

The source is in the earlier supplied `ZEFMEXPORT.zip` →
`EXPORT/ZEdit_ZEFM_src.jar`. The archive is **not** bundled into this release.

## Using the Notes editor (implemented in v37)

Open a file in ZEFM, select a word or put the cursor within it, then choose
**Notes → Annotate Selected Word / Word at Cursor...**. The popup displays
an existing note if one has been saved, or starts with an empty text area.
**Save Note**, **Delete Note**, and **Close** are available. Close prompts before discarding
unsaved changes in the note popup (v40). Saving a note does not modify the open
document or mark its buffer dirty. **Notes → Notes for Current File...**
lists the file's notes. Double-click a listed note to edit it.

New notes live in `$XDG_DATA_HOME/zefm/word_notes.json` (default
`~/.local/share/zefm/word_notes.json`) on Linux/macOS. The file is local,
UTF-8, and written atomically with private (0600) permissions for new files.
The JSON schema keeps the original 4 fields. Notes are keyed per file and
per exact word; a word occurring more than once in the same file shares the
same note. A saved file is required before attaching a note.

Word detection includes Unicode combining marks, so `בֿ` and `ייִדיש` remain
single words. Selecting text is also supported for punctuation-rich or
mathematical expressions; the selection is used as the exact key.

## Migrating historical MyISAM records (partial; no direct raw extraction)

`ZEFMdb.zip` contains the original MyISAM `.frm`, `.MYD`, and `.MYI` files.
These files are *not* directly parsed by this Python version. They must be
restored into a suitable, isolated legacy-compatible MySQL/MariaDB instance
first. Do not point a production database server at an untrusted archive;
back up the original ZIP and use a disposable migration environment.
Compatibility depends on the original database engine/version and schema.

Once the old tables can be queried, optionally install PyMySQL **in that
migration environment only** and run:

```sh
python3 -m pip install pymysql
python3 -m zefm.storage.export_legacy_tables notes ~/notes-export.jsonl --database ZEFMdb --user YOUR_DB_USER
python3 -m zefm.storage.export_legacy_tables dictionaries ~/dictionaries-export.jsonl --database ZEFMdb --user YOUR_DB_USER
```

The first command exports legacy Notes, the second produces a raw dictionary
export for a **later** dictionary migration. Credentials are prompted for
rather than accepted as CLI arguments. For a Unix socket, pass `--socket`.
These exports contain private data: store them locally, not in a public
repository or shared ZIP.

The exporter uses only read queries, checks the exported record count against
`COUNT(*)`, and rejects undecodable UTF-8. It writes UTF-8 JSONL via atomic
replacement. It will not replace an existing export unless `--force` is given.

To load a validated Notes JSONL/JSON export into ZEFM:

```sh
python3 -m zefm.storage.import_legacy_notes ~/notes-export.jsonl
```

The import is atomic; existing identical `(filename, word)` keys are retained
unless `--replace` is given. The importer's optional `--output` argument lets
you test using a temporary path rather than altering live Notes data.

**Important:** historical `filename` values may be browser URL-style names or
old filesystem paths, whereas newly created local Notes use resolved absolute
paths. Imported data deliberately retains the original filename string.
Notes whose old filename differs from the current file path will not appear
in the current-file list until we implement an explicit, reviewed filename
mapping facility. No automatic guesses or destructive rewrites are made.

## v40: Notes saving usability

The desktop note dialog now puts **Save Note** at the **top** of the popup,
where it remains visible even with a large editor font. `Ctrl+S` on Linux,
or `Command+S` on macOS, also saves a note while the dialog has focus.
The popup prompts before discarding modified text. Successful saves update
the main editor's status line; if the note changed through the browser while
the popup was open, the desktop save warns instead of overwriting it.

The local file-manager's **Notes** page is no longer read-only. Select
**Add Note**, or **Edit note** beside an existing word, enter the note text,
and press **Save Note**. Saves use the same UTF-8 JSON note store as the editor.
A form opened before another update cannot overwrite a newer note (HTTP 409);
reopen the form to see the current content. The browser form uses a CSRF token
and rejects access outside the chosen file-manager root. No MySQL is needed.
